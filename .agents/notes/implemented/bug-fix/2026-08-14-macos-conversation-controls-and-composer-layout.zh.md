# Agent Note：macOS 对话控件展示真实状态

Status: implemented

[English](2026-08-14-macos-conversation-controls-and-composer-layout.md) | 中文

## Problem

macOS 对话标题和输入区把箭头、运行轨迹页签与智能体预设标签表现为可交互控件，但没有绑定动作。用户消息同时使用左侧头像和右侧正文，使同一条消息分散到对话区两端。输入区在可变行数文本框外使用会扩张到最大建议高度的 frame，导致空草稿占用过多空间，并且用户不能直接调整高度。

## Decision

标题改为不带展开 affordance 的普通文本。对话标题持有真实的对话/运行轨迹选择状态：对话展示完整会话，运行轨迹展示现有工具卡，并在工具尚未运行时展示空状态。两个标签都是 plain 样式按钮，当前项显示下划线。

macOS 客户端读取 `agentPreset.list`，通过菜单展示所选会话的预设，并且只在会话为空时调用 `agentPreset.select`。已开始的会话仍可打开菜单，但选项被禁用，菜单会说明预设已经锁定。客户端复用 Host 现有的预设列表和选择方法，不增加 macOS 专用预设来源或协议方法。

用户消息把名称、气泡和头像渲染为同一个右侧消息组。助手消息继续使用左侧头像和全宽正文。

输入区使用持久化高度，默认值为 116 pt，可调范围为 104 至 300 pt。顶部拖动手柄调整高度时，输入区保持固定在底部。去除首尾空白后为空的草稿仍不能发送，发送与取消继续使用现有路径。

## Alternatives considered

**保留占位控件并增加帮助文本。** 拒绝：可见页签、展开箭头或选择标签表示存在可用动作，帮助文本不能修复无效点击区域。

**增加独立的运行轨迹协议和模型。** 拒绝：客户端已经把工具调用和结果折叠为 `ToolCard`，这些数据足以支持当前运行轨迹视图。

**用 AppKit 文本视图替换 SwiftUI 文本框。** 拒绝：缺陷来自外层 frame 的尺寸建议，不是文本系统能力缺失。明确的 SwiftUI 高度和拖动手势可以保留现有草稿与提交路径。

## Consequences

macOS 连接流程现在会在工作区、会话和凭据发现之外调用捆绑 Host 已有的 `agentPreset.list` 方法。Host 接受预设变更后，客户端会立即更新所选会话摘要。

运行轨迹页签是同一会话的工具聚焦投影，不是第二套事件存储。在运行轨迹中选择工具仍会打开现有详情面板。输入区高度通过应用偏好跨启动保留，并受上下限约束，因此不会覆盖对话区或压缩掉操作控件。

`swift test --package-path apps/macos` 覆盖完整 macOS package 和真实 sidecar 握手。前台应用验证覆盖输入区紧凑默认高度和两个拖动方向；现有开发运行脚本修改二进制后，开发 bundle 需要临时 ad-hoc 签名才能启动。
