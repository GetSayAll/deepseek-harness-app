# Agent Note: macOS V1 深海工作台

Status: proposed

[English](2026-08-14-macos-v1-deep-ocean-workbench.md) | 中文

## Problem

原生 macOS 客户端已经暴露 Harness 会话与交互协议，但当前 SwiftUI 视图还没有以桌面信息密度承载 Web 客户端的工作区、对话、运行轨迹、详情、设置、目标和子智能体信息架构。如果各页面独立实现，列宽收缩、输入区接管、状态颜色和控件会逐步分化。

## Proposal

DS Harness macOS `0.1.1` 使用 [macOS 设计规范](../../../../apps/macos/DESIGN.md) 中的 V1“深海工作台”方案。客户端保留 Web 客户端的三栏层级和控件位置，同时使用 SwiftUI 和窄范围 AppKit 桥接实现原生窗口、菜单、Popover、Sheet、键盘和辅助功能行为。

实现把输入区作为一个稳定座位，由普通输入、审批、结构化问答、计划审阅和子智能体只读状态共享。工具与轨迹检查使用常驻右侧栏。设置使用独立原生窗口，工作区选择使用附着 Sheet。

浅色主题是 `0.1.1` 的视觉基线。深色主题可以暂时跟随系统获得基本可用性，但不能改变组件层级，也不能阻塞浅色主题验收。

## Alternatives considered

**通过 WebView 嵌入 Web 客户端。** 这种方式可以更快复现浏览器界面，但会放弃原生窗口、菜单、焦点、辅助功能和桌面控件行为，也会把 Web 可执行 UI 与语义化原生协议混在一起。

**保留当前最小 SwiftUI 页面并由每个功能局部定样式。** 这种方式不需要共享设计阶段，但协议覆盖扩展后，导航、状态、卡片和交互模式会产生差异。

**使用高对比度的 V2 深色侧栏。** 更强的色彩分割削弱了安静的阅读表面，也不符合已确认的视觉方向。V1 的浅色材质侧栏和克制蓝青强调继续作为基线。

## Acceptance criteria

- 主窗口保存侧栏、中央栏和详情栏宽度，并遵循设计规范中的收缩顺序。
- 空白、普通会话、工具详情、运行轨迹、审批、问答、计划审阅、目标与后台任务、子智能体、设置和工作区选择状态使用统一的 V1 组件语言。
- 输入区接管保留普通输入草稿，并占用同一个布局座位。
- `0.1.1` 浅色主题符合设计规范中的颜色、排版、键盘、减少动态效果和辅助功能要求。
- 原生载体继续只传递语义；插件不能注入 Swift View、JavaScript 或新的展示 RPC 方法。

## Risks

生成式视觉稿包含示例文案和不能作为像素级源文件的几何细节。视觉稿与运行时数据或原生控件行为冲突时，书面设计规范负责尺寸、行为和优先级。

复现 Web 客户端的信息密度可能需要针对分栏宽度、焦点或文本编辑增加 AppKit 桥接。大范围 AppKit 所有权会增加生命周期复杂度，因此 SwiftUI 继续作为默认实现界面。
