# DS Harness macOS 0.1.1 设计规范

本文是 DS Harness macOS `0.1.1` 的界面实现参考。视觉方向为 V1“深海工作台（Deep Ocean Workbench）”。V2 深色侧栏方案不属于实现范围。

视觉稿用于表达布局、层级、密度和风格，本文中的尺寸、状态和交互规则用于开发验收。视觉稿中的 AI 生成文字、日期或示例路径与产品语义冲突时，以本文、原 Web 客户端行为和原生协议数据为准。

## 产品目标

macOS 客户端保留 Web 客户端的工作区、会话、对话、运行轨迹、工具详情、设置和交互接管结构，同时使用 SwiftUI 与有限的 AppKit 桥接提供原生窗口、键盘、菜单、Sheet、Popover 和辅助功能行为。

界面优先支持长时间阅读和高频操作。品牌颜色只强调选中、进度和主操作；长文本、代码和运行记录保持低干扰背景。桌面空间用于同时呈现上下文，不把详情页、审批和结构化问答改造成不必要的全屏流程。

## 窗口与响应式布局

主窗口默认尺寸为 `1280 × 800 pt`，最小尺寸为 `900 × 600 pt`。窗口采用统一标题栏，交通灯保留系统位置；标题栏内容可延伸到全尺寸内容区域，但不得覆盖交通灯的安全区域。

主界面使用三列结构：左侧栏、中央内容、右侧详情。展开侧栏默认 `280 pt`，允许在 `264...420 pt` 内调整；收起后固定 `56 pt`。中央内容优先保证至少 `640 pt`。右侧详情默认 `360 pt`，允许在 `300...520 pt` 内调整。窗口不足时先收起右侧详情；宽度低于 `1024 pt` 时自动把左侧栏收为图标轨道，用户仍可手动展开。

侧栏和右侧详情的宽度偏好应保留。窗口重新变宽后恢复用户上次的展开宽度，而不是写入临时压缩后的宽度。

中央对话正文最大宽度为 `748 pt`。输入卡最大宽度为 `780 pt`，比正文每侧多 `16 pt`。正文、任务卡、目标栏和交互接管卡共享同一中轴；不得为单个状态引入新的水平基准。

## 颜色

以下颜色是浅色主题的实现基准：

| 名称 | 值 | 用途 |
|---|---:|---|
| `backgroundBase` | `#F7F9FC` | 主窗口和对话底色 |
| `sidebarFill` | `#EDF2F8` | 展开侧栏和设置导航 |
| `surfacePrimary` | `#FFFFFF` | 输入卡、设置卡、Sheet |
| `surfaceSecondary` | `#F3F6FA` | 次级卡片、代码浅底 |
| `brandPrimary` | `#4176E6` | 主按钮、选中、进度、链接 |
| `brandHighlight` | `#35CFE8` | 运行指示、品牌节点、小面积光晕 |
| `textPrimary` | `#18202C` | 标题和正文 |
| `textSecondary` | `#667184` | 说明、元数据和占位文字 |
| `borderSubtle` | `rgba(24,32,44,0.10)` | 普通边框和分隔线 |
| `selectionFill` | `rgba(65,118,230,0.10)` | 会话、工具行和设置导航选中态 |
| `success` | `#35B86B` | 完成和连接状态 |
| `warning` | `#E99A32` | 等待审批和等待状态 |
| `danger` | `#E45858` | 停止、删除和失败 |

背景光晕仅用于空白首页和输入卡周围，使用低于 `12%` 不透明度的蓝青径向渐变。普通会话、设置页和长文本区域不得使用大面积渐变。状态颜色必须同时配合图标或文字，不能仅凭颜色传达结果。

深色模式不属于 `0.1.1` 的视觉验收范围。实现可以遵循系统颜色获得基本可用性，但不得为此改变浅色主题的布局和组件接口。

## 字体与排版

界面字体使用系统 `SF Pro Text`；大标题可由系统自动使用 `SF Pro Display`；代码、路径、命令和 JSON 使用 `SF Mono`。中文由系统回退到苹方。不要捆绑第三方字体。

| 样式 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| Hero | `28/36 pt` | Semibold | 空白首页主标题 |
| Page title | `20/28 pt` | Semibold | 设置页和主要面板标题 |
| Section title | `16/24 pt` | Semibold | 卡片和消息段落标题 |
| Body | `15/25 pt` | Regular | 助手正文和用户消息 |
| Control | `14/22 pt` | Medium | 按钮、导航和工具行 |
| Metadata | `12/18 pt` | Regular | 时间、状态、统计和说明 |
| Code | `13/22 pt` | Regular | 代码块和终端输出 |

正文段落最大宽度跟随 `748 pt` 内容列。中文正文段间距为 `10 pt`；列表项间距为 `6 pt`。标题不得为了容纳控件降到 Metadata 字号，空间不足时先截断会话标题并保留完整 Tooltip。

## 间距、圆角与阴影

基础间距单位为 `4 pt`。常用间距为 `8、12、16、20、24、32 pt`。侧栏内边距 `12 pt`；对话滚动区横向安全边距至少 `32 pt`；设置内容区横向内边距 `40 pt`。

圆角分级：小型控件 `8 pt`，按钮和工具行 `10 pt`，普通卡片 `12 pt`，输入与交互接管卡 `16 pt`，大型设置窗口内部容器 `20 pt`。图标按钮使用圆形或 `8 pt` 圆角，不混用药丸形状。

普通卡片只使用边框，不默认添加明显阴影。输入卡、Popover、Sheet 和交互接管卡可以使用 `0 8 24 rgba(30,55,90,0.10)` 的环境阴影。悬停不改变整体高度或边框宽度。

## 图标和品牌

操作图标优先使用 SF Symbols，线宽统一采用 Regular 或 Medium。常规图标为 `16 pt`，紧凑元数据为 `14 pt`，侧栏收起轨道为 `18 pt`，空白首页品牌图形为 `64...72 pt`。

鲸鱼与连接节点用于 App 图标、侧栏品牌和空白首页，不用于每个工具或普通消息。会话正文中的助手标记可使用 `28 pt` 简化鲸鱼图标。工具类型使用语义图标：终端 `terminal`、文件 `doc`、搜索 `magnifyingglass`、差异 `doc.badge.gearshape`、审批 `exclamationmark.shield`、子智能体 `point.3.connected.trianglepath.dotted`。

## 通用控件

主按钮高度 `32 pt`，水平内边距 `14 pt`，使用 `brandPrimary` 背景和白色文字。次按钮使用白色或透明背景与 `borderSubtle` 边框。图标按钮标准点击框 `28 × 28 pt`，侧栏收起状态为 `36 × 36 pt`。危险按钮默认使用描边和 `danger` 文字，只有不可逆确认的最终步骤才使用实心红色。

控件状态：Hover 使用 `6%` 深色覆盖；Pressed 使用 `10%`；Disabled 降低至 `40%` 不透明度并取消阴影；键盘焦点使用 `2 pt brandPrimary` 外描边和 `2 pt` 间隔。所有图标按钮必须提供 `.help` 和辅助功能标签。

输入框高度至少 `32 pt`。多行输入卡默认高度约 `136 pt`，文本区最多增长到 `336 pt`，超出后内部滚动。发送按钮为 `40 × 40 pt` 圆形，运行时原位替换成停止按钮；替换不得造成输入卡重排。

菜单使用原生 `Menu`；临时列表使用 `Popover`；需要选择或确认且会阻断当前窗口的流程使用附着 `Sheet`；破坏性确认使用 `confirmationDialog` 或 `alert`。右侧工具和事件详情始终是第三列，不使用 Sheet 或浮层。

## 页面说明

### 空白会话

侧栏保持完整导航，中央把品牌标题、工作区选择、预设选择和输入卡组合成一个略高于垂直中心的任务起点。用户未选择工作区时输入卡不可发送，并以“选择一个工作区开始”解释原因。蓝青光晕只围绕输入卡，不能延伸到侧栏或标题栏。

### 普通会话与工具详情

顶部显示会话层级、预设/状态和“对话/运行轨迹”标签。用户消息使用最大 `525 pt` 的浅蓝气泡；助手消息采用开放式文档排版。任务、工具、目标和上下文事件使用正文内的紧凑行或卡片，不扩大成聊天气泡。

点击工具行后在右侧打开详情。详情头固定，正文独立滚动；输入参数使用浅色 JSON 卡，终端输出使用深色代码卡。切换工具时保留详情栏宽度，但重置该工具内部的展开和复制状态。

### 运行轨迹

轨迹页保留顶部会话标签和底部输入卡。工具栏、时间轴、按轮次分组的事件表是中央内容；事件详情复用右侧详情列。SYSTEM、USER、ASSISTANT、TOOL 使用低饱和类型标签，状态仍由成功、等待、失败图标表达。

表格滚动时工具栏和时间轴保持在视图顶部。选中事件必须同时更新表格高亮、时间轴焦点和右侧详情。搜索只过滤或聚焦轨迹内容，不改变原始事件顺序。

### 审批、问答和计划审阅

三种状态统一接管底部输入座位，正常输入卡保持挂载但不可交互，避免草稿丢失。交互卡宽度与输入卡一致，最大正文高度 `336 pt`，超出后卡内滚动。

审批使用淡琥珀背景，展示原因、命令或工具参数、权限范围以及“拒绝/允许一次”。问答使用原生单选或复选语义，每个问题支持选项、补充回答和跳过；全部问题满足要求后才启用提交。计划审阅按文档格式展示计划，“拒绝/修改计划/批准计划”从左到右排列，批准是唯一主按钮。

### 长期目标与后台任务

目标栏固定在会话标题下方，显示目标、阶段、轮次和进度，暂停、编辑、清除使用紧凑图标按钮。目标栏不得随消息滚出视图。输入卡上方提供命令提示，但不阻止普通自然语言输入。

后台任务入口位于会话标题右侧，使用锚定 Popover 展示任务状态。任务在窗口关闭后继续运行时必须明确说明。Popover 只提供查看、停止或取消等单任务操作；完整历史进入独立任务列表，不在 Popover 中无限增长。

### 子智能体会话

标题面包屑表达父会话到子会话的层级，侧栏在父会话下缩进显示子智能体。页面顶部状态条说明创建来源、运行状态和返回父会话入口。子智能体不可直接发送时，底部使用只读栏解释限制并提供停止操作，不显示可编辑输入框或发送按钮。

### 设置

设置为独立原生窗口，默认 `920 × 700 pt`，最小 `760 × 560 pt`。左侧导航固定 `188 pt`，顺序为模型、智能体预设、插件、更新、通用。右侧内容滚动，窗口底部显示 Host 连接状态。

模型页用提供方卡片呈现凭据状态、Base URL、默认模型和模型目录。API Key 只能写入和显示已配置状态，不能回读明文。预设页使用两列等高卡片，默认预设以浅蓝底和蓝色边框表示；查看与复制位于卡片底部。插件页使用一个展开、其余折叠的配置卡，插件列表由标签页进入。

更新页显示当前版本、更新通道、手动检查入口和版本历史链接。“接收预览版更新”使用持久化开关，默认关闭；发布说明由 Sparkle 更新窗口展示，不在设置页复制一份可漂移的内容。

### 工作区目录选择

目录选择使用附着 Sheet，保留被调暗的主窗口上下文。Sheet 建议尺寸 `760 × 570 pt`，包含收藏栏、面包屑、搜索、目录列表、路径摘要、新建文件夹、隐藏文件选项以及取消/打开。双击目录进入，单击选择，Return 打开，Escape 取消。无权限、重复工作区或创建失败通过 Sheet 内错误说明处理，不关闭用户当前路径。

## 运行状态与反馈

加载使用骨架或小型 ProgressView，避免整页中心 Spinner。流式消息仅在最后一条助手消息末尾显示活动指示。工具状态固定为等待、运行、完成、停止和失败；状态变化不改变行高。

Toast 用于短暂成功反馈，例如“已复制”或“设置已保存”，显示 `2.5 s`。需要用户修正的错误留在相关卡片或字段旁。Host 断开时主内容保留，只在顶部或状态栏显示重连信息；不得用空白页替换现有会话。

## 键盘与辅助功能

`⌘N` 新建会话，`⌘⇧O` 添加工作区，`⌘,` 打开设置，`⌘⇧R` 重新连接 Host，`⌘Enter` 使用忙碌状态的另一发送行为，Escape 关闭 Popover、Sheet 或当前详情。普通 Enter 的发送行为遵循设置；多行输入必须保留换行方式。

侧栏、会话标签、轨迹表和设置导航支持方向键移动。所有状态图标提供文字标签；动态更新使用适度的辅助功能公告，不逐 token 宣读流式文本。界面支持系统减少动态效果、增加对比度和键盘全访问。

## 动效

普通状态过渡 `160...200 ms`，侧栏和详情列展开 `300 ms`，使用系统 ease-in-out。Popover 与 Sheet 使用系统动画。流式、进度和运行指示可以持续动画，但必须响应“减少动态效果”。布局动画不得让拖动分隔条落后于指针；拖动期间关闭宽度缓动。

## SwiftUI 实现边界

现有 `NavigationSplitView` 可以继续承担主导航，但需要显式保存侧栏和详情宽度偏好。对话、轨迹和详情应拆成稳定挂载的区域，切换标签或交互接管不应销毁输入草稿和滚动状态。

优先使用 `Material`、`Form`、`Table`、`DisclosureGroup`、`Menu`、`Popover`、`Sheet`、`NavigationSplitView` 和 SF Symbols。仅在窗口工具栏、分隔条、文本编辑或焦点行为无法满足规范时增加窄范围 AppKit 桥接。不得把 Web 页面嵌入 WebView，也不得通过原生协议传输可执行 UI。

建议组件边界：`AppFrameView` 管理三列和宽度；`SidebarView` 管理品牌、工作区和会话树；`ConversationHeaderView` 管理层级和标签；`ConversationTimelineView` 管理消息与工具行；`ComposerSeatView` 管理正常输入及审批、问答、计划接管；`DetailsPanelView` 管理工具详情；`TrajectoryView` 管理轨迹；设置各页面作为独立 Section View。

## 0.1.1 验收

`0.1.1` 的界面实现至少满足以下结果：主窗口在默认和最小尺寸下无内容遮挡；侧栏、中央内容和右侧详情遵循收缩顺序；空白、普通会话、工具详情、审批、问答和设置模型页达到 V1 视觉层级；其余视觉稿对应页面具备相同组件语言；草稿在标签切换和交互接管后保留；键盘焦点和 VoiceOver 能到达所有操作；浅色主题颜色、字号和状态符合本文。
